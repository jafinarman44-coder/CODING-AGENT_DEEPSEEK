**Stage:** Source implementation and isolated JVM validation

## Implemented

1. `AgentOrchestrator` connects intent classification, planning, supervision, and controlled node execution.
2. `IntentClassifierNode` routes Bengali and English requests into conversation, summary, meeting notes, task organization, document outline, translation, external action, or unknown intent.
3. `PlannerNode` creates typed multi-step plans. Meeting-note workflows chain meeting extraction into task organization.
4. `SupervisorAgent` rejects request/plan mismatches, empty/oversized plans, and plans referencing unavailable nodes. It stops the workflow on node exceptions.
5. High-risk/external-action plans require explicit confirmation. Even after confirmation, the action is rejected because no external-action provider exists; no email, message, payment, deletion, or publishing action is performed.
6. `WatchdogAgent` limits plan length and elapsed execution time.
7. Nodes included: conversation fallback, extractive summary, line-based meeting notes, keyword-grounded task extraction, document outline, explicit translation-unavailable response, and clarification.
8. `DefaultAgentRuntime` assembles the available nodes for app-level integration in a later UI/wiring step.
9. Unit tests added for Bengali routing, summary output, confirmation gating, missing external provider, honest LLM boundary, watchdog timeout, node exception handling, and request/plan mismatch.

## Capability boundaries and next dependencies

The current agent core is a real deterministic orchestration foundation, not a generative AI model. The summarizer selects source sentences; meeting/task extraction uses explicit line/keyword rules; document output is an outline. The next implementation stage must add a real model-provider abstraction/adapter and then connect an approved local or remote model before describing open-ended generation as available. App UI wiring and persistence of agent sessions are also separate work.
